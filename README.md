# cloud_run_product_report — D2C Sales & Returns Report

A scheduled Google Cloud Run service that generates and emails a daily **D2C Sales & Returns Report** for Frido.

## What it does

- Runs daily via **Cloud Scheduler**
- Queries **BigQuery** (`frido-429506.production.fact_all_platform_sales_report`) for D2C Shopify orders (MyFrido + Mobility channels)
- Computes **30+ KPIs** — gross revenue, net revenue, cancellation %, RTO %, CIR %, exchange %, ASP, AOV, COD vs Prepaid split, daily averages
- Generates a **responsive HTML email** with 9 data sections and red/bold threshold highlighting
- Attaches a full **Excel file** (`Frido_D2C_Orders_{start}_{end}.xlsx`) with 21 columns of raw order-level data
- Sends to stakeholders via **Microsoft Graph API** (Microsoft 365)

## Project structure

```
main.py               # Core logic: queries, KPI computation, HTML + Excel generation, email dispatch
send_test.py          # Test sender — HTML email only (no Excel), reads TO/CC from env vars
preview.py            # Local preview — writes preview.html, no email sent
requirements.txt      # Python dependencies
Dockerfile            # Container definition (python:3.11-slim)
env_flags.yaml.example  # Template for Cloud Run deploy config. Copy to env_flags.yaml and fill in values.
gen_docs.py           # Script to regenerate DOCUMENTATION.docx
DOCUMENTATION.docx    # Full developer documentation (generated by gen_docs.py)
```

> **Never commit `env_flags.yaml`** — it contains real credentials. It is listed in `.gitignore`.

## Quick start

```bash
# Generate HTML preview locally (no email)
python preview.py
# Open preview.html in browser

# Send test email (HTML only, no Excel) — set env vars first
python send_test.py

# Full run (HTML + Excel attachment)
python main.py
```

Requires GCP service account key at `../sa_key.json` for local runs, and env vars from `env_flags.yaml`.

## Deploy

```bash
bash deploy.sh
```

Requires `gcloud` CLI authenticated with Cloud Run Admin + Secret Manager Admin on `frido-429506`.

## Data source

Single BigQuery table: `frido-429506.production.fact_all_platform_sales_report`

**D2C filter applied to all queries:**
```sql
Channel = 'Shopify'
AND SubChannel IN ('MyFrido', 'Mobility')
AND OrderId NOT LIKE '%_EX%'
AND DATE(OrderDate) >= '{start_date}'
AND DATE(OrderDate) < '{cutoff}'
```

**Date window:** Rolling 30 days with a 15-day lag for order status maturity.

## Report sections

1. **KPI Cards** — Gross Rev, Net Rev (incl & excl GST), Daily Avg Gross, Cancel %, RTO %, CIR %, Exch %, ASP, AOV, COD vs Prepaid split
2. **Monthly Trend** — 6-month rolling table (Gross Rev, Qty, ASP, Cancel%, RTO%, CIR%, Exch%, Tot Ret ₹/%, Retained ₹/%)
3. **Revenue Leakage by Category** — Category-level breakdown with retained % highlighted if below average
4. **Top 20 Products by Revenue** — Best sellers with return breakdown; Tot Ret% flagged if > 1.5× overall threshold
5. **Top Leakage Products** — Products losing most ₹ to returns (min 20 units, sorted by absolute leakage)
6. **Exchange Watch** — Products with high exchange rates (size-chart issue signals)
7. **Category-wise All Products** — Full drill-down, one section per category
8. **Definitions** — Metric glossary embedded in the email
9. **Footer** — Period label and D2C definition

## Excel attachment

File name: `Frido_D2C_Orders_{start_date}_{cutoff}.xlsx`  
Sheet: `D2C Orders` — 21 columns of raw order-level data (OrderId, OrderDate, Dispatch/Delivered/Cancelled dates, Channel, SubChannel, PaymentType, State, City, Pincode, SKU, Product, Category, Qty, Price incl/excl GST, Order Status, Tracking Status, Return Reason, Return Sub Reason).

## Environment variables

| Variable | Purpose |
|---|---|
| `GCP_CREDENTIALS_B64` | Base64-encoded GCP service account JSON |

| `OTP_FRIDO_CLIENT_ID` | Azure AD application (client) ID |
| `OTP_FRIDO_CLIENT_SECRET` | Azure AD client secret |

| `EMAIL_TO` | Comma-separated TO recipients |
